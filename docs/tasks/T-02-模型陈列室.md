# T-02 模型陈列室

- 依赖：无

## 任务（审查方写）

### 背景
以后会有很多美术任务（新单位、新建筑）。审查需要一张图就能看到所有体素模型在四个朝向下的样子，不用进游戏去找。

### 要做的事
1. **`tools/gallery.html`**：一个独立页面，直接用浏览器打开就能看。
   - 页面里放一个隐藏的 `<canvas id="stage" hidden></canvas>`，因为 `gfx.js` 加载时需要它。
   - 按顺序加载 `../game/js/util.js`、`../game/js/gfx.js`、`../game/js/models.js`，不加载其他游戏脚本。
   - **单位区**：遍历 `UNIT_MODEL` 的每个键，每个单位一行：
     - 四个朝向 `[1,0]`、`[0,1]`、`[-1,0]`、`[0,-1]`，用 `sprite(key, UNIT_MODEL[key], dir, 1)` 烘焙。
     - 第五格是残骸：坦克（`t72`、`t64`）用 `wreckify(hullOf(UNIT_MODEL[key]()), 7)`，其他用 `wreckify(UNIT_MODEL[key](), 7)`，朝向 `[1,0]`。
     - 行首写单位键名。
   - **建筑与道具区**：`mApt(1,false)`、`mApt(1,true)`、`mHouse(3,false)`、`mHouse(3,true)`、`mChurch()`、`mSub()`、`mHangar(1,false)`、`mRubble(1)`、`mForest(5)`、`mBridgeRuin(true)`、`mTB2()`、`mCrate(1)`，朝向 `[1,0]`，每个下方写函数名。
   - 显示方式：把烘焙结果的 `.c`（一个 canvas）放进页面，CSS 放大 3 倍，`image-rendering: pixelated`；每格下方用小字标出像素尺寸 `w×h`。
   - 背景深色 `#15202a`，每个模型放在一个带细边框的格子里，格子之间留间距。
2. **`tools/gallery-shot.js`**：`node tools/gallery-shot.js <输出目录>`
   - 用 playwright 打开 `tools/gallery.html`（`file://` 路径），视口宽 1600，截整页图保存为 `<输出目录>/gallery.png`。
   - 页面有任何 `pageerror`，或者 console 里有 `error`（忽略 `net::` 和证书相关的网络错误），就打印错误并以退出码 1 结束。
   - 写法参照 `tools/playtest.js`。

### 验收标准
1. `node tools/check.js` 通过（它会顺带检查新文件的语法）。
2. `node tools/gallery-shot.js docs/tasks/shots/T-02` 退出码为 0，生成 `docs/tasks/shots/T-02/gallery.png`。
3. 截图里能看到全部 12 个单位的 4 个朝向和残骸，以及 12 个建筑和道具，每个都有清晰的标签。
4. 没有改动 `game/` 目录下的任何文件。
