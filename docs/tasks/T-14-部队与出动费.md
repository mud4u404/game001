# T-14 部队名册、出动费与出击选队

- 改动范围：`game/js/data.js`、`game/js/battle.js`、`game/js/ui.js`、`game/index.html`、`tools/playtest.js`
- 依赖：T-11, T-13

## 任务（审查方写）

### 背景
负责人的设计：
- 玩家拥有一支会损耗的部队，每关自己决定派谁、派多少；
- 派得越多，出动费越高；打得省，资金就充裕；
- 两辆坦克、五个步兵班、一辆坦克加一个步兵班，都应该是可行的打法。

这张卡把“每关固定 3 个单位”改成“从名册里自选出击”。

### 要做的事
1. **数值**（`data.js` 的 `UNITS`）：给乌方单位加 `cost`（出动费）和 `price`（购买价）两个字段。

   | 单位 | cost | price |
   |---|---|---|
   | tdf | 1 | 2 |
   | atgm | 1 | 3 |
   | d30 | 1 | 3 |
   | bmp2 | 2 | 4 |
   | t64 | 2 | 5 |
   | neptune | 2 | 5 |
   | magura | 1 | 2 |

2. **名册**（`CAMP.roster`）
   - `freshCamp()`：
     - `aid: 6`；
     - `roster` 为 `t64`、`atgm`、`d30`、`tdf`、`tdf` 这 5 条；
     - `nextRid: 6`。
   - 每条记录的格式：`{ rid: 1, type: 't64', wrecked: false }`，`rid` 从 1 开始递增，由 `nextRid` 分配。
   - 读取没有 `roster` 字段的旧存档时，补上默认名册。
   - **兜底**：进入任务卡时，如果名册里没有未损毁的 `tdf`，自动加一条 `tdf`，并 `toast('国土防卫部队补充了一个步兵班')`。
3. **任务数据**：每个任务新增两个字段。
   - `slots`：出击上限。1-1 为 5，1-2 为 6，1-3 为 6，2-1 为 5。
   - `pool`：允许出击的兵种。
     - 1-1、1-2、1-3：`['t64', 'atgm', 'd30', 'tdf', 'bmp2']`；
     - 2-1：`['t64', 'atgm', 'neptune', 'tdf', 'bmp2']`。
   - `squad` 保留，只作为“默认选择 + 默认位置”。
   - **部队奖励**（`grant`）：
     - 1-2 新增 `grant: { type: 'bmp2', text: '第72机械化旅调来一辆 BMP-2。' }`，只在主线成功并接受结果时加入名册；
     - 2-1 新增 `grant` 的触发方式不同：进入该任务（`CAMP.mission` 第一次到达它）时，把一辆 `neptune` 加入名册，文字“海岸导弹营调来一辆“海王星”发射车。”。
     - 这两种触发方式用两个不同的字段名，自己命名清楚，并用 `CAMP.flags` 防止重复发放。
4. **选队界面**（`index.html` 的 `#bCard` + `ui.js`）
   - 在“作战要点”后面、“部署部队”按钮前面，加一个 `class="full"` 的区块“出击编制”。
     - 右侧显示 `已选 n / slots · 出动费 x · 可用援助 y`。
     - 下面每条名册记录一张卡片：头像、`short`、`cost`。
       - 损毁的显示为灰色，标“损毁”，不可选；
       - 不在 `pool` 里的显示为灰色，标“不适用”，不可选。
     - 点击切换选中。以下两种情况点击无效，并给出 toast：
       - 已达到 `slots`，toast “编制已满”；
       - 出动费超过可用援助，toast “援助不足”。
   - **免费名额**：选中的第一个 `tdf` 出动费为 0，卡片上标“免费”。
   - 默认选择：按 `M.squad` 的兵种顺序，每个兵种选名册里第一条可用的记录。选不到的兵种就跳过。
   - 一个都没选时，“部署部队”按钮禁用。
   - 点击“部署部队”的顺序：
     1. 先存 `CAMP.pre`（T-11 已做），这一步必须在扣费之前；
     2. 扣除出动费；
     3. 执行 `newBattle(CAMP.mission, 选中的名册记录)`；
     4. 执行 `beginDeploy()`。
   - 标题简介里的“指挥三支小分队，守住基辅的门户。”改为“指挥一支特遣队，守住基辅的门户。”。
5. **战斗初始化**（`battle.js`）
   - `newBattle(mi, picks)`：
     - `picks` 缺省时，按上面的默认选择规则从名册生成（`showTitle` 的背景战斗也走这条路）；
     - 每个单位带上 `u.rid`，`B.squad = picks`。
   - 位置规则：
     - 某兵种在 `M.squad` 里、并且是该兵种的第一个单位时，用 `M.squad` 给的位置；
     - 否则在 `M.deploy` 里按顺序找第一个格子，要求上面没有单位、`moveCost(u, x, y)` 有限。
   - HUD 的 roster 和 Tab 切换改为遍历 `B.squad`，用 `rid` 找单位。
     - 这样两个同类单位（比如两个步兵班）能分别显示；
     - 阵亡的单位显示为“损毁”。
     - 用 grep 查全所有 `B.mission.squad` 的用法。
   - roster 最多 6 个单位时，不能溢出或遮挡右侧的任务目标。必要时调整 `.roster` 的 CSS，比如改成两列或缩小卡片。
6. **战后结算**
   - 接受结果时，战斗中阵亡的单位在名册里标为 `wrecked: true`。
   - 选择“重新部署”时，因为回滚到了 `CAMP.pre`，名册自动恢复原状。
7. **补给商店**（`renderShop`）
   - 保留现有的升级项。
   - 新增“购买部队”：`pool` 不限，列出 `tdf`、`atgm`、`d30`、`bmp2`、`t64` 五种，价格为 `price`。
   - 新增“维修”：每条损毁记录一项，价格为 `Math.ceil(price / 2)`，买下后 `wrecked = false`。
   - 分组标题分别是“升级”“部队”“维修”，风格与现有商店一致。
8. **playtest**：机器人每关开始前，把 `CAMP.aid` 设为至少 10，并把名册里所有记录设为未损毁，保证每关都能跑到（写法参照原来补电网的那一行）。选队走默认选择，不要改决策逻辑。

### 第 1 轮
审查提交：60253ec
结论：需修改

整体完成得很好：选队、免费名额、出动费、商店三个分组、兵种奖励都正确，截图里的选队界面也清楚。有一个 bug 需要修：

1. **损毁标记的时机不对（必须修）**
   - 现在 `killUnit` 在单位阵亡的瞬间就把名册记录标成 `wrecked: true`。
   - 出错场景：玩家在自己的回合里让我方单位阵亡，比如无人艇撞击自毁、被推进河里。随后玩家点“作战预案”回退本回合，`restoreSnapshot` 让单位在战场上复活了，但名册里它仍是损毁状态。任务结束后，这个活着的单位会被当成损毁。
   - 修法：
     - 删掉 `killUnit` 里改名册的那一行；
     - 在 `continueCampaign()` 接受结果时统一处理：把 `B.units` 里 `team === 'ua' && u.dead && u.rid` 的单位对应的名册记录标为损毁；
     - 这一步放在 `CAMP.mission++` 之前。
     - 卡片原文就是“接受结果时，战斗中阵亡的单位在名册里标为 `wrecked: true`”。
   - 在执行记录里写一段验证：
     - 1-1 开战后用 `window.__sf` 让一个步兵班阵亡，此时名册仍是未损毁；
     - 调用 `restoreSnapshot(B.snap)` 后单位复活；
     - 结束任务、接受结果后，名册里它仍是未损毁。
2. **重拍 `hud6.png`**：现在这张图的地图上几乎看不到我方单位。我用同样的配置实际检查过，6 个单位的位置是对的（t64@4,4、atgm@4,2、d30@2,5、tdf@0,2、tdf@0,3、bmp2@1,3）。请重拍一张 6 个单位都清楚可见的部署阶段截图。
3. 顺手清理：`tools/playtest.js` 里残留的 `page.isVisible('#gameover')` 那一行删掉，它引用的元素在 T-11 里已经删除了。
