## 任务（审查方写）

### 背景
燃烧的残骸、受损的建筑和爆炸现在冒的是 2D 小圆点烟，和 3D 画面不搭。这张卡把烟换成 3D 场景里的柔和烟团：会上升、随风飘、逐渐变大变淡。**火星、碎屑、闪光等其余特效保持不变。**

### 要做的事
1. **烟团贴图**（`scene3d.js`）：
   - 用一个 64 × 64 的 canvas 画径向渐变：中心 `rgba(255,255,255,0.9)`，边缘完全透明；
   - 做成一个 `THREE.CanvasTexture`，所有烟团共用。
2. **烟团对象池**（`scene3d.js`，新增一段 `// ---------- smoke ----------`）：
   - 每个烟团是一个 `THREE.Sprite`，材质 `THREE.SpriteMaterial({ map: 上面的贴图, transparent: true, depthWrite: false })`；
   - 颜色、透明度按烟团单独设置，所以每个 Sprite 用自己的材质；
   - 预先建好 80 个放进 `V3.units` 同级的一个组里，不用时 `visible = false`，循环复用，**运行中不要 new 新的 Sprite**。
   - 新增函数 `smoke3D(wx, wy, wz, kind)`，从池里取一个空闲烟团。`kind` 取值：
     - `'fire'`：浓黑烟。颜色 `#2a2a2a`，初始大小 3、4 秒内长到 11，初始不透明度 0.65，线性降到 0；上升速度每秒 5 个单位。
     - `'dust'`：受损建筑的灰烟。颜色 `#8a8680`，大小 4 → 12，不透明度 0.5 → 0，上升每秒 3。
     - `'blast'`：爆炸烟。颜色 `#5a5650`，大小 2 → 9，2.5 秒，不透明度 0.7 → 0，上升每秒 4，出生时带一点随机水平速度。
   - 所有烟团受一个固定的风：每秒沿 +x 方向漂 1.5 个单位。
   - 在 `render3D()` 里按真实时间（`performance.now()` 的差值）更新位置、大小和透明度，到期就收回。
3. **持续冒烟**（`scene3d.js`，每帧在 `render3D()` 里）：
   - 每个有残骸的格子（`TILEAT(x, y).wreck`）每秒约 3 个 `'fire'` 烟团，从格子中心上方 y ≈ 3 冒出，位置带 ±1.5 的随机偏移；
   - 受损未倒塌的建筑（`BLD[t.t] && t.hp > 0 && t.hp < t.max`）每秒约 2 个 `'dust'` 烟团，从建筑顶部冒出（楼房 `b` 约 y 16，其余约 y 9）；
   - 已倒塌的建筑（`hp === 0`）每秒约 1 个 `'dust'`，从 y ≈ 3 冒出。
   - 用累计时间控制频率，不要每帧都冒。
4. **爆炸烟**：在 `scene3d.js` 新增 `smokeBurst3D(x, y, size)`（参数是格子坐标），一次放出 `4 * size` 个 `'blast'` 烟团。在 `render.js` 的 `explode()` 里，照 `flash3D` 的写法调用它。
5. **关掉对应的 2D 烟**（`render.js`）：在 3D 模式下（`HD` 为 true 时）不要再生成这些 2D 烟粒子：
   - `renderBattle()` 末尾残骸和受损建筑的那两条冒烟语句（`kind: 'smoke'` 的两条）；
   - `explode()` 里 `kind: 'smoke'` 的那一段循环。

   火星（`kind: 'fire'`）、碎屑、2D 模式下的一切都保持原样。

### 第 1 轮
审查提交：88ad0e2
结论：通过（审查方修了发烟分配）

对象池、三种烟、风、2D 烟的开关都照卡做对了。`smokeEmit()` 有两处问题，审查方直接修了：
- 同一种烟共用一个累计量，`while` 循环在第一个格子上就把它耗光，场上有多个残骸时只有第一个冒烟。现在每次从该类格子里随机选一个；
- 没有残骸时累计量照样增长（`Math.max(1, 0)`），第一辆车被击毁时会一口气喷出几十个烟团。现在没有可冒烟的格子时累计量清零。
另外把残骸的发烟频率从每秒 3 个提到 5 个，不透明度 0.65 → 0.75，烟柱更明显。

注意：无显卡的测试环境每帧约 1 秒，而每帧的时间步长上限是 0.1 秒，所以截图里的烟比真实浏览器里稀薄得多，这不是 bug。
