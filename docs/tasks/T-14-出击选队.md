# T-14 出击前选队

- 改动范围：`game/js/data.js`、`game/js/battle.js`、`game/js/ui.js`、`game/index.html`
- 依赖：T-13

## 任务（审查方写）

### 背景
玩家一方固定 3 个单位，放在俄乌战场上显得很怪。这张卡做两件事：
- 让玩家在简报的任务卡上，从兵力池里挑选出击编制；
- 部分任务的编制上限提高到 4 个。

### 要做的事
1. **任务数据**（`data.js` 的 `MISSIONS`）
   - 每个任务新增 `slots`（出击上限）和 `pool`（可选单位）两个字段。
   - `squad` 保持“默认编制 + 默认位置”的含义，并按下表补充默认单位：

   | 任务 | slots | pool | squad 新增 |
   |---|---|---|---|
   | 1-1 hostomel | 3 | `['t64', 'atgm', 'd30', 'tdf']` | 不变 |
   | 1-2 irpin | 4 | `['t64', 'atgm', 'd30', 'tdf', 'bmp2']` | `tdf: [2, 4]` |
   | 1-3 skybyn | 4 | `['t64', 'atgm', 'd30', 'tdf', 'bmp2']` | `bmp2: [2, 1]` |
   | 2-1 odesa | 4 | `['t64', 'atgm', 'neptune', 'tdf', 'bmp2']` | `tdf: [4, 1]` |

   - 先确认表里的新默认位置都在该任务的 `deploy` 列表里，并且是空地。如果不是，在执行记录里说明，然后换成 `deploy` 里最近的空地。
2. **战斗初始化**（`battle.js`）
   - `newBattle(mi, types)`：`types` 缺省时取 `Object.keys(M.squad)`，把它存到 `B.squadTypes`。
   - 生成单位时：
     - 若 `type` 在 `M.squad` 里，用 `M.squad` 给的位置；
     - 否则按顺序在 `M.deploy` 里找第一个格子，要求上面没有单位、`moveCost` 有限。
       - `moveCost` 需要一个单位对象，可以先建出单位再检查。
   - 代码里所有用 `Object.keys(B.mission.squad)` 表示“本场我方单位”的地方，都改用 `B.squadTypes`。
     - 至少包括 `ui.js` 的 roster 和 Tab 切换；
     - 自己用 grep 查全。
3. **选队界面**（`index.html` + `ui.js`）
   - 在 `#bCard` 里，“作战要点”后面、“部署部队”按钮前面，加一个 `class="full"` 的区块：
     - 标题 `<span class="ph">出击编制</span>`；
     - 右侧显示 `已选 n / slots`；
     - 下面是 `pool` 里每个单位一张卡片（按钮）：头像（`pimg(pilot)`）、`short` 名称、生命值格、“移动 n”，与 HUD 的 roster 卡片风格一致；
     - 点击卡片切换选中；选中的卡片高亮，未选中的半透明；
     - 已满 `slots` 时，点未选中的卡片没有反应，并出 `toast('编制已满')`。
   - 用全局变量 `PICK` 保存当前选择。`showMissionCard()` 每次打开时重置为 `Object.keys(M.squad)`。
   - 一个都没选时，`#btnDeploy` 禁用。
   - `#btnDeploy` 点击时先执行 `newBattle(CAMP.mission, PICK.slice())`，再执行 `beginDeploy()`。
     - `#btnRetry` 走的是 `showBriefing(); showMissionCard();`，会回到选队界面，这是预期行为。
   - 标题画面的简介文字“指挥三支小分队，守住基辅的门户。”改为“指挥一支特遣队，守住基辅的门户。”。
4. HUD 的 roster 在 4 个单位时不能溢出或遮挡任务目标。如有必要，调整 `index.html` 里 `.roster` 相关的 CSS。

### 验收标准
1. `node tools/check.js` 通过。
2. `node tools/playtest.js /tmp/pt-T-14` 输出 `ERRORS none`，退出码 0。机器人使用默认编制，不需要改 playtest。
3. 截图放进 `docs/tasks/shots/T-14/`：
   - `pick.png`：1-2 的任务卡，出击编制显示 5 张卡片，默认选中 4 张；
   - `hud4.png`：1-2 部署阶段，左侧 roster 显示 4 个单位，布局正常。

   截图方法不限，可以在临时目录写一个 playwright 脚本，但不要提交脚本。
4. 执行记录里写一段验证：在 1-1 取消 D-30、选上步兵班，开战后场上是 T-64、反坦克组、步兵班，步兵班位于 `deploy` 里的空地。

- 不要把兵力池做成需要用援助解锁，这一步先全部开放。
