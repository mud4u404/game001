- 改动范围：`game/js/data.js`、`game/js/battle.js`、`game/js/ui.js`、`game/index.html`、`tools/playtest.js`
- 依赖：—

## 任务（审查方写）

### 背景
负责人的设计决定：
- 不再用一条贯穿全战役的“电网”血条；
- 每一关有自己的战略目的（主线），外加若干次要任务；
- 完成程度决定收获（援助资金）；
- 主线失败不结束游戏，玩家可以重打，也可以接受失败继续推进（失败会带来后果）；
- 整个战役不再有“游戏结束”。

### 要做的事
1. **删除全局电网**
   - `CAMP.grid`、`CAMP.gridMax`、`checkDefeat` 里的电网判定、`snapshot` / `restoreSnapshot` 里的 `grid`、`endMission` 里的电网修复、`gridCells()`、战役地图和 HUD 上的电网显示、结算里的“电网损失 / 电网剩余”、`UPGRADES` 里的 `grid`（抢修电网）、`#gameover` 整个画面及其按钮，全部删除。
   - 用 `grep -n "grid\|电网\|gameover" game/js/*.js game/index.html` 查全，逐处处理。
   - `BLD` 的 `grid: true` 字段改名为 `civil: true`，表示民用建筑。敌方 AI 仍然优先打这类建筑，打分逻辑保持不变，只改字段名。
   - 建筑被击中：`B.stats.bldHit++`（替换原来的 `gridLost`），toast 改为 `${info.name} ${coord(x, y)} 被击中`。
   - 平民遇难：只做 `B.stats.civLost++`，toast 改为“一批平民遇难”。
   - `renderTip` 里建筑说明的“被击中一次，电网 -1。”改为“民用建筑。”。
   - 旧存档里残留的 `grid` 字段忽略即可。
2. **任务目标重写**（`data.js` 的 `MISSIONS[*].objectives`）
   - `kind` 只保留 `primary`（主线，每关恰好 1 个）和 `bonus`（次要）。
   - 删掉所有“坚守到第 N 回合结束”。
   - `reward` 是援助资金。各关目标如下（`eval` 沿用现有写法，新增的统计字段在 `newBattle` 的 `stats` 里初始化为 0）：

   | 任务 | 主线（reward 5） | 次要 |
   |---|---|---|
   | 1-1 | `runway` 炮击跑道，制造 3 个弹坑（不变） | `heli` 击落 2 架直升机（2）；`village` 民用建筑被击中不超过 2 次，`B.stats.bldHit`，inverse max 2（1） |
   | 1-2 | `evac` 护送至少 2 批平民过河（不变） | `evac3` 3 批平民全部过河，`B.stats.evac` max 3（2）；`sub` 变电站完好（1）；`orlan` 击落奥兰-10（1） |
   | 1-3 | `block` 最多 1 辆车突破西侧（不变，inverse） | `armor` 击毁 4 辆装甲车辆（2）；`cmd` 击毁团指挥车（1）；`village` 民用建筑被击中不超过 1 次（1） |
   | 2-1 | `landing` 上岸的敌军不超过 1 个（inverse max 1） | `naval` 击沉 2 艘巡逻艇（2）；`heli` 击落卡-52（1）；`city` 民用建筑被击中不超过 2 次（1） |

   - `sub` 的 eval：
     - 用 `countTiles(B, t => t.t === 'S' && bldAlive(t))` 数出完好的变电站；
     - 返回 `{ cur: 这个数, max: 1 }`，以 `cur >= max` 为完成。
     - `bldAlive` 定义在 `battle.js`，运行时是全局可见的。
   - `landing` 的 eval：
     - 数存活的、`team === 'ru'`、不是空中单位、脚下地块不是水面（`!isWater(TILEAT(x, y))`）的敌军；
     - 返回 `{ cur, max: 1, inverse: true }`。
   - 目标的 `text` 用简短的中文动宾句，风格与现有目标一致。
3. **结算与方案 A**（`ui.js` 的 `showDebrief` / `continueCampaign`，以及 `battle.js` 的 `endMission`）
   - 主线失败（`!res.win`，包括小队覆灭）时，结算画面显示两个按钮：
     - `#btnRetry`，文字“重新部署”：放弃本次结果，重打本关；
     - `#btnNext`，文字“接受结果，继续”。
   - 主线成功时只显示 `#btnNext`（“返回战役地图”），和现在一样。
   - 重打必须真正回滚：
     - 在 `#btnDeploy` 点击时（进入部署之前）存一份 `CAMP.pre = JSON.parse(JSON.stringify(Object.assign({}, CAMP, { pre: null })))`；
     - `#btnRetry` 执行 `CAMP = Object.assign(freshCamp(), CAMP.pre)`，再回到本关任务卡（`showBriefing(); showMissionCard();`）；
     - 回滚后，本次获得的援助、后果标记都不保留。
   - 接受结果时照常执行 `consequence`（1-1 的 `runwayOpen` 保留），`CAMP.mission++`。
   - 结算的统计格子：
     - 把“电网损失 / 电网剩余”换成“建筑被击中”（`bldHit`）和“平民撤离”（`evac`）；
     - 其余格子不变。
4. **playtest**
   - 删掉 `tools/playtest.js` 里补满电网的那两行（注释加 `C.grid = C.gridMax`）；
   - 如果它读取 `grid` 做输出，也一并去掉；
   - 不要改机器人的决策逻辑。

### 验收标准
1. `node tools/check.js` 通过。
2. `node tools/playtest.js /tmp/pt-T-11` 输出 `ERRORS none`，退出码 0。
3. `grep -n "电网\|CAMP.grid\|gameover" game/js/*.js game/index.html` 没有结果。
4. 执行记录里写一段验证（用 playwright 或 `window.__sf`）：1-1 里手动让主线失败，结算出现两个按钮；点“重新部署”后 `CAMP.aid` 回到出发前的数值。
5. 截图放进 `docs/tasks/shots/T-11/`：
   - `debrief-fail.png`：主线失败的结算，两个按钮都可见；
   - `hud.png`：1-2 战斗 HUD，左上角不再有电网，右侧是新的主线和次要目标。

### 不要做
- 不要改地图、敌军、增援和回合数。
- 不要做部队 / 出动费经济，那是 T-14。
